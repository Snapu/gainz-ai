# 21: Stripe Managed Payments Checkout, Canonical Webhook Sync, 3-Day Grace & Customer Portal

**Parent:** TICKET-017  
**Labels:** `ready-for-agent`, `tracer-bullet`, `domain`, `application`, `infrastructure`, `presentation`  
**Blocked by:** TICKET-018  
**Status:** ready-for-agent

**What to build:** Enable end-to-end subscription monetization at **7.99 EUR/month (incl. VAT, cancellable monthly to period end)** via **Stripe Managed Payments**—letting athletes subscribe in mobile browsers and installed PWAs through a server-generated Hosted Checkout redirect without loosening Content-Security-Policy, unlocking Pro AI coaching via idempotent canonical Stripe webhook synchronization, protecting gym workouts with a 3-day `past_due` payment grace period, and providing 1-tap invoice and cancellation self-service via the Stripe Billing Customer Portal in the global header menu.

## Acceptance Criteria

- [ ] Database schema adds `user_subscriptions(user_id primary key, provider, provider_subscription_id unique, provider_customer_id, price_id, status, cancel_at_period_end, current_period_end, grace_ends_at, last_event_created, updated_at)` and `processed_webhook_events(event_id primary key, processed_at)` (indexed on `processed_at` with 30-day probabilistic pruning), locked down with RLS to `service_role` only.
- [ ] Authorization precedence grants highest priority to active `Subscription` (`status IN ('active', 'trialing')` including `cancel_at_period_end = true` while `current_period_end > now()`, or `status = 'past_due'` while `grace_ends_at > now()`) with `15` `coach` / `50` `classify` daily fair-use limits and zero `FreeAllowance` consumption.
- [ ] `billing` Edge Function `action: "checkout"` uses server-configured `STRIPE_MONTHLY_PRICE_ID` and strict `APP_PUBLIC_URL` return URLs (never client-supplied URLs or unvalidated `Origin` headers), pins an explicit `Stripe-Version` header, sets `managed_payments[enabled] = true`, binds `client_reference_id = caller.userId` + `subscription_data[metadata][user_id] = caller.userId`, redirects to Customer Portal whenever `status IN ('active', 'trialing', 'past_due', 'unpaid', 'paused')` (preventing duplicate subscriptions even when `cancel_at_period_end = true`), and reuses `customer = provider_customer_id` when re-subscribing after `canceled`.
- [ ] `billing` Edge Function `action: "portal"` mints a fresh Stripe Billing Customer Portal session (`POST /v1/billing_portal/sessions`) whenever `provider_customer_id` exists—including `status = 'canceled'` so former subscribers can still download past VAT receipts.
- [ ] A new `billing-webhook` Edge Function (`verify_jwt = false`) verifies raw request bodies against `Stripe-Signature` (`t` + `v1` constant-time HMAC with 300s replay tolerance), performs a read-only fast-path check on `processed_webhook_events(event_id)`, extracts the subscription ID across post-2025 Basil+ and legacy Stripe payloads (`invoice.parent.subscription_details.subscription ?? invoice.subscription`), fetches canonical state via `GET /v1/subscriptions/{id}` (`items.data[0].current_period_end ?? current_period_end`, failing closed if `metadata.user_id` is missing and never matching by email), and commits `processed_webhook_events(event_id)` + `user_subscriptions` inside **one atomic PL/pgSQL RPC** with a monotonic write guard (`last_event_created` + terminal `canceled` lock) and atomic 3-day `grace_ends_at` handling (`past_due` preserves existing grace deadline; recovery to `active` clears it).
- [ ] Client validates `https://*.stripe.com` URLs before top-level checkout/portal navigation (preserving strict `script-src` / `frame-src` CSP), captures `?checkout=success` at bootstrap into `sessionStorage` before hash-router `/loading` redirects strip queries, routes post-load checkout returns to the Coach view, and polls server `status` briefly with `<UiTelemetryLoader>`—never unlocking Pro access from the URL flag alone.
- [ ] Upgrade Card primary CTA launches checkout (disclosing Stripe / Link billing & order management), an orange `past_due` warning banner links directly to payment-method recovery during the 3-day grace window, and `GlobalHeaderActions` renders the localized (`de` / `en`) Membership section showing active/cancelling expiration status and opening the Customer Portal.
- [ ] Behavioural seam tests cover `checkout` duplicate-subscription protection, `portal` access for active and cancelled customers, `billing-webhook` HMAC replay rejection, transient Stripe `GET` retry safety (event ID not burned before DB commit), concurrent out-of-order webhook updates with distinct `event.id`s, Basil+ schema parsing, 3-day `past_due` grace lifecycle, and client `?checkout=success` bootstrap polling.
