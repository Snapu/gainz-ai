# 18: End-to-End FreeAllowance Gate, Starter Badge & Paywall Pause

**Parent:** TICKET-017  
**Labels:** `ready-for-agent`, `tracer-bullet`, `domain`, `application`, `infrastructure`, `presentation`  
**Blocked by:** None (can start immediately)  
**Status:** done

**What to build:** Deliver the complete vertical monetization foundation from database authorization to client UI so every newly registered athlete receives a pause-safe starter `FreeAllowance` of **30 AI coaching requests** (capped at 5/day during the free phase) and **40 background classification calls** with no calendar expiration, sees a live `X / 30` starter badge in the Coach and Plan views while proactive daily briefings motivate gym attendance, and transitions smoothly without error toasts to a clear Upgrade Card when all 30 coaching requests are consumed—while manual workout logging, Google Sheets sync, and deterministic `trainingInsights` stay permanently free and 100% offline-capable.

## Acceptance Criteria

- [x] Server configuration unconditionally requires `ABUSE_PREVENTION_PEPPER` (`>= 32` chars) and derives a version-prefixed pseudonymous `subject_digest = 'v1:' || HMAC_SHA256(ABUSE_PREVENTION_PEPPER, google_sub)` (supporting optional `ABUSE_PREVENTION_PEPPER_PREVIOUS` lookup for future key rotation).
- [x] Database schema introduces `free_allowance_usage(subject_digest primary key, coach_used, classify_used, updated_at)` with RLS enabled, `service_role`-only grants (`REVOKE ALL` from `public`, `anon`, `authenticated`), `SET search_path = ''` on RPCs, an index on `updated_at`, and probabilistic 24-month inactivity pruning (`updated_at < now() - interval '24 months'`, unaffected by 30-day daily-quota pruning).
- [x] Unified atomic authorization & refund RPCs enforce identical deadlock-free lock ordering (`ai_daily_usage(user_id, usage_date)` -> `free_allowance_usage(subject_digest)` -> `ai_daily_global_usage(usage_date)`), enforce free-phase daily limits (`5` `coach` / `20` `classify` per UTC day) alongside global daily caps, evaluate `canUseCoach` (`coach_used < 30`) and `canUseClassify` (`classify_used < 40`) independently so exhausting 40 background classifications never blocks remaining coaching requests, and return the full `Entitlement` snapshot (including server `evaluatedAt` timestamp) alongside `Quota`.
- [x] Upstream Gemini failures refund both daily quota and (only when admission recorded `admitted_source = 'free_allowance'` and the daily counter decrement matched `count > 0`) `free_allowance_usage`, gated on an atomic `processing -> failed` request transition so refunds are strictly idempotent per request.
- [x] A new `billing` Edge Function (`verify_jwt = false` at the function gateway, authenticated via Google OIDC/OAuth caller verification, isolated from shared Edge helper back-imports in boundary checks) serves `action: "status"`, returning the caller's current `Entitlement`.
- [x] `ai-coach` enforces the `Entitlement` gate prior to upstream model calls (returning HTTP `402` with `{ error: "payment-required", entitlement }` when unentitled vs. `429` on daily/global rate caps), skips the `402` gate on `action: "recover"` so already-admitted in-flight completions are delivered after mobile screen unlock, and piggybacks fresh `entitlement` state onto completed `200` SSE/JSON responses.
- [x] A new 4-layer `billing` client module (`domain`, `application`, `infrastructure`, `presentation`) models pure `Entitlement` eligibility rules, validates responses via Zod Anti-Corruption Layer schemas, caches the latest `Entitlement` synchronously in scoped `localStorage` (ignoring stale snapshots with older `evaluatedAt` and clearing reactively on sign-out), and passes all module and shared-presentation cycle boundary checks.
- [x] On a cold login (`entitlement === null`), `aiOrchestrator` allows optimistic pass-through so initial onboarding mesocycle generation succeeds seamlessly and hydrates `Entitlement` from the piggybacked response; while `canUseCoach` is true during `FreeAllowance`, proactive daily briefings remain active on app open.
- [x] When HTTP `402` (`"payment-required"`) occurs or `!canUseCoach` / `!canUseClassify` is cached, the client records zero Sentry exceptions, skips the `recoverPendingRequest` polling loop, clears optimistic user message placeholders, suppresses red error toasts, pauses automatic `ensureSessionAdvice`, plan regeneration, and background classification independently, and keeps offline gym logging & insights 100% functional.
- [x] Coach and Plan views (via their view-model composables, never calling stores directly) display a localized `<UiBadge>` starter counter (`X / 30`) during `FreeAllowance` and render the localized (`de` / `en`) Upgrade `<UiCard>` when `!canUseCoach`—contrasting **"With GainzAI Pro (7,99 € / Monat inkl. MwSt., monatlich kündbar)"** against **"Always Free Without Pro"** (workout logging, training history, rest timer, Google Sheets sync, calculated insights) with a Stripe / Link billing notice.
- [x] Behavioural seam tests cover the `ai-coach` and `billing` (`status`) Edge handlers, SQL lock-ordering/schema invariants, `useBillingStore`, `useAiOrchestratorStore`, Coach/Plan view-models, and architecture boundary tests.
